At both widths the two versions produce the same arrangement: at 360px the request list and the aside stack in one column, and at 1280px they sit side by side. What differs is where that relationship is written. In my Module 3 CSS, the body is a CSS Grid with named areas (main and aside), and one media query at 52em (832px) changes grid-template-columns to 2fr and minmax(15rem, 1fr). In the Bootstrap version the same idea lives in the HTML: container sets a centred maximum width (1140px at 1280px), row creates a wrapping flex container, and col-12 col-lg-8 and col-12 col-lg-4 mean full width by default, then 8/12 and 4/12 from 992px. One visible consequence is the breakpoint: Module 3 goes to two columns at 832px, Bootstrap only at 992px, so a 900px window looks different.

Bootstrap saved effort because the card, alerts, list group, badges and form validation styling came from class names instead of rules I wrote. The cost is heavier markup, a much larger stylesheet, and accepting Bootstrap's spacing and colours instead of my own design tokens. My custom CSS gives finer control, such as logical properties for RTL and a custom focus ring, but I had to design and test every rule myself.
